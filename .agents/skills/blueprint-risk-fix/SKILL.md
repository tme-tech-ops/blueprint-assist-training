# Blueprint Risk Fix — AI-Assisted Remediation (Optional)

This skill is an **optional enhancement** for teams using Blueprint Assist alongside the Blueprint Architecture Visualizer. It is **not required** for risk detection, fix previews, or the `--fix` CLI flag — those all work standalone without this skill installed.

When present, this skill enables AI assistants to read risk findings, prioritize them, and generate context-aware YAML patches using the fix patterns below.

## When to Use

- After running `generate_visualizer.py` and reviewing the risk panel
- When the user shares a `risk-fixes.yaml` file (generated by `--fix` flag)
- When the user asks to fix specific risk categories or rule violations
- When the user pastes a risk finding and asks "how do I fix this?"

## Prerequisites

1. **Load `blueprint-rules.md`** — the compliance rules that risk findings map to
2. **Identify the source blueprint** — the YAML files that need to be modified
3. **Have the risk findings** — either from a visualizer HTML, a `risk-fixes.yaml`, or pasted text

## Workflow

### Step 1: Get the Risk Findings

The risk engine outputs findings with these fields:

```json
{
  "id": "r5",
  "severity": "high",
  "node": "my_vm",
  "title": "Hardcoded Credential Detected",
  "description": "Property 'password' appears to contain a hardcoded secret value.",
  "recommendation": "Replace the hardcoded value with: { get_secret: { get_input: password_secret_name } }",
  "riskCategory": "security",
  "ruleRef": "SC-001",
  "confidence": "high",
  "autoFixable": true,
  "fixCode": "inputs:\n  password_secret_name:\n    type: secret_key\n    ..."
}
```

If the user has a `risk-fixes.yaml` file, load it:
```bash
cat risk-fixes.yaml
```

If the user is looking at the visualizer, ask them to click "Show Fix" on the risk card or share the risk details.

### Step 2: Prioritize Fixes

Apply fixes in this order:
1. **High severity + autoFixable** — these are critical and have known patches
2. **High severity + manual** — need human decision but are critical
3. **Medium severity + autoFixable** — easy wins
4. **Low/Info** — address if time permits

### Step 3: Apply Fix Patterns

Each `ruleRef` maps to a specific fix pattern. Use the patterns below.

---

## Fix Patterns by Rule Reference

### SC-001 — Hardcoded Credential

**Before:**
```yaml
node_templates:
  my_node:
    properties:
      password: "my_literal_password"
```

**After:**
```yaml
inputs:
  password_secret_name:
    type: secret_key
    hidden: false
    display_label: Password Secret Name
    description: Name of the secret storing the password.
    constraints:
      - type: <secret_schema>
    display:
      group: credentials
      index: 1

node_templates:
  my_node:
    properties:
      password: { get_secret: { get_input: password_secret_name } }
```

### ND-001 — Isolated Node (No Relationships)

**Before:**
```yaml
node_templates:
  orphaned_node:
    type: dell.nodes.SoftwareComponent
    # No relationships defined
```

**After:**
```yaml
node_templates:
  orphaned_node:
    type: dell.nodes.SoftwareComponent
    relationships:
      - type: dell.relationships.depends_on
        target: <upstream_node>
```

**How to choose the target:** Look at the node's `get_input` / `get_attribute` references — if it reads attributes from another node, that node is the dependency target. If unclear, ask the user.

### ND-002 — Missing Delete Lifecycle

**Before:**
```yaml
node_templates:
  my_task:
    type: dell.nodes.SoftwareComponent
    interfaces:
      dell.interfaces.lifecycle:
        create:
          inputs:
            playbook_path: ansible/install.yaml
```

**After:**
```yaml
node_templates:
  my_task:
    type: dell.nodes.SoftwareComponent
    interfaces:
      dell.interfaces.lifecycle:
        create:
          inputs:
            playbook_path: ansible/install.yaml
        delete:
          inputs:
            playbook_path: ansible/uninstall.yaml
```

**Note:** The delete playbook must reverse the create actions. Check `blueprint-rules.md` ND-003 for the list of persistent changes to revert (mount points, fstab, systemd, crontab, firewall rules, etc.).

### ND-003 — Orphaned Attachment

Add post-delete verification:
```yaml
interfaces:
  dell.interfaces.lifecycle:
    postdelete:
      inputs:
        playbook_path: ansible/verify-cleanup.yaml
```

### IM-003 — Unpinned Plugin Version

**Before:**
```yaml
imports:
  - plugin:ansible-plugin
```

**After:**
```yaml
imports:
  - plugin:ansible-plugin?version= >=4.1.8.0,<5.0.0.0
```

Use the Plugin Version Reference in `blueprint-rules.md` to find the correct minimum version.

### TD-001 — Non-Standard TOSCA Version

**Fix:**
```yaml
tosca_definitions_version: dell_1_1
```

### TD-002 — Legacy nativeedge.* References

Search and replace all occurrences:
- `nativeedge.nodes.*` → `dell.nodes.*`
- `nativeedge.relationships.*` → `dell.relationships.*`
- `nativeedge.interfaces.*` → `dell.interfaces.*`
- `nativeedge_ansible` → `dell_ansible` (in implementation paths)

### IN-003 — Missing Display Label

```yaml
inputs:
  my_input:
    display_label: My Input    # Title Case, no underscores
```

### IN-004 — Missing Description

```yaml
inputs:
  my_input:
    description: |
      Human-readable description of what this input controls
      and what values are acceptable.
```

### IN-005 — Missing Hidden Property

```yaml
inputs:
  my_input:
    hidden: false    # or true if the input should not appear in the wizard
```

### IN-007 — Unbounded Input (No Constraints)

Choose the appropriate constraint based on the input type:

```yaml
# String inputs
constraints:
  - pattern: ^[a-zA-Z0-9_-]+$
    error_message: "Only alphanumeric characters, hyphens, and underscores are allowed."

# Integer inputs
constraints:
  - in_range: [1, 100]
    error_message: "Value must be between 1 and 100."

# Boolean inputs
constraints:
  - valid_values: [true, false]
    error_message: "Must be true or false."
```

### IG-001 — No Input Groups

```yaml
input_groups:
  - name: infrastructure
    display_label: Infrastructure
    collapsible: true
    index: 0
    inputs:
      - <list infrastructure inputs>
  - name: application
    display_label: Application
    collapsible: true
    index: 1
    inputs:
      - <list application inputs>
```

**Note:** `input_groups` must go in the top-level `blueprint.yaml` (BS-004).

### CP-001 — No Capabilities

```yaml
capabilities:
  endpoint:
    description: "Primary endpoint for the deployed resource"
    value: { get_attribute: [<main_node>, <relevant_attribute>] }
```

## Batch Fix Mode

When the user runs `generate_visualizer.py --fix`, it produces a `risk-fixes.yaml` file:

```yaml
# Auto-generated by Blueprint Architecture Visualizer
# Review each fix before applying to your blueprint
blueprint_source: /path/to/blueprint
generated_at: 2026-05-26T09:00:00Z
total_risks: 84
fixable_risks: 42

fixes:
  - risk_id: r5
    rule_ref: SC-001
    severity: high
    title: "Hardcoded Credential Detected"
    node: my_vm
    target_file: blueprint.yaml
    fix_type: replace_property
    fix_code: |
      inputs:
        password_secret_name:
          type: secret_key
          ...
```

To apply: Review each entry, then use the fix patterns above to modify the source YAML.

## Validation After Fixes

After applying fixes, always:

1. **Re-run the visualizer** to verify risk count decreased:
   ```bash
   python generate_visualizer.py <blueprint_dir>
   ```

2. **Lint the blueprint** if `bpa` is available:
   ```bash
   bpa lint-blueprint --file blueprint.yaml --verify
   ```

3. **Validate node templates** if plugin source is available:
   ```bash
   bpa validate-blueprint-nodes --file blueprint.yaml
   ```
